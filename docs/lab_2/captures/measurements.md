# Вимірювання записів логічного аналізатора (ЛР2, п. 4.3–4.4)

Записи: `all.vcd` (сесія: cap whoami, accel, wr2, nack, lcd, servo 0, servo 180, adc, uart) і
`nack-order.vcd` (свіжа сесія: cap nack, cap nack, cap wr2, cap nack). Wokwi, `$timescale 1ns`.
Канали: D0 = SCL, D1 = SDA, D2 = PWM серво, D3 = UART TX, D4 = LED_MARK, D5 = ADC_MARK.

Як міряли:
- точні часи фронтів — прямо з VCD (крок 1 нс);
- протоколи — `sigrok-cli 0.7.2` (декодери `i2c`, `pwm`, `uart`, `timing`) на вікнах, вирізаних
  `tools/vcd_window.py <in.vcd> <t0> <t1> <out.vcd>` (час у вікні рахується від t0);
- `downsample` не потрібен: найдовше вікно (servo, 46,8 мс) — 46,8 млн семплів при 1 ГГц,
  PulseView і sigrok-cli відкривають його без проміжного проріджування.

Приклад: `sigrok-cli -i whoami.vcd -I vcd -P i2c:scl=D0:sda=D1 -A i2c=start:stop:ack:nack:address-read:address-write:data-read:data-write`.

## I²C

Послідовності (S — START, P — STOP, A — ACK, N — NACK; адреси 7-бітні):

| Вікно | Послідовність |
|---|---|
| whoami | S 68 W A · 75 A · P — S 68 R A · 68 N · P |
| accel | S 68 W A · 3B A · P — S 68 R A · 00 A · 00 A · 00 A · 00 A · 40 A · 00 N · P |
| wr2 | S 68 W A · 6B A · далі нічого: другого байта (0x00) і STOP немає, SCL = 0 |
| nack (all) | START немає, адреси немає — див. «nack після wr2» |
| lcd ('C' = 0x43) | S 27 W A · 4D A · P — S 27 W A · 49 A · P — S 27 W A · 3D A · P — S 27 W A · 39 A · P |
| nack_clean | S 69 W N · P |
| wr2_again | S 68 W A · 6B A · далі нічого, як у wr2 |
| nack_after_wr2 | START немає, адреси немає |

- SCL (whoami, 2 транзакції): 36 періодів, усі рівно **10,000 мкс → 100,0 кГц**; t_HIGH = t_LOW = 5,000 мкс.
- Транзакція «адреса + 1 байт» від S до P — 195,0 мкс; пауза між транзакціями whoami (P → S) — 39,0 мкс.
- Читання 6 байтів accel (S → P) — 645,0 мкс. raw = 00 00 / 00 00 / 40 00 → X = 0, Y = 0, Z = 0x4000 = 16384 (1 g при ±2 g).
- LCD, PCF8574 (P0 = RS, P1 = RW, P2 = EN, P3 = BL, P4..P7 = D4..D7): 4D/49 — старший півбайт 4 з EN = 1/0, 3D/39 — молодший — 3; RS = 1, BL = 1 → дані 0x43 = 'C'.
  Паузи між транзакціями 46,5 / 50,8 / 48,9 мкс, весь символ (перший S → останній P) — 926,2 мкс.
  Уся команда `cap lcd` — 68 транзакцій (set_cursor 0xC0 + 16 символів × 4), 16,504 мс.

### wr2: SCL лишається в 0

- Після ACK на байт 0x6B (останній такт SCL — спад через 218,53 мкс після фронту D4) SCL лежить у 0, SDA = 1.
  START на початку є, STOP немає.
- У вікні SCL = 0 до кінця (200 мкс за побудовою вікна). У повному записі SCL лежить у 0 до наступної команди:
  all.vcd — з 20,533992 до 24,467165 с (**3,933 с**), nack-order.vcd — з 21,667333 до 24,933833 с (**3,267 с**).
  Таймаут прошивки ~100 мс (D4 = 100,6 / 101,3 мс) і `I2C_RECOVER` лінію SCL на шині не відпускають.

### nack після wr2 (вікна nack з all.vcd і nack_after_wr2 — однакові)

Час від фронту D4: SDA↓ 25,00 мкс (при SCL = 0); SCL↑ 30,00 — шину відпущено; SDA↑ 33,52 при SCL = 1 — STOP;
SCL↓ і SDA↓ разом на 35,00 (SCL першим — не START); SCL↑ 38,52; SDA↑ 45,00 при SCL = 1 — STOP. Далі обидві лінії в 1.
**START немає, адреса 0x69 не передається, ACK/NACK немає**; D4 — 48,75 мкс (проти 145,28 мкс у чистому випадку).
Прошивка при цьому друкує `st=OK`.

### nack_clean

S через 33,52 мкс після фронту D4, адреса 0x69 + W, на 9-му такті SDA = 1 → **NACK**, P на 138,53 мкс. Прошивка
друкує `st=OK` і тут, хоча на шині NACK (docs/journal.md, проблема 9).

### Самоперевірка: mpu6050_init (all.vcd, 2,43–2,75 с)

UART: три рядки `I2C_RECOVER where=wr err=0x20 isr=0x00008003`, далі `2745 SELFTEST mpu6050 status=WARN who=0x68 tries=3 err=SLEEP`.

| Час, с | На шині |
|---|---|
| 2,427518 | `S 68W A 75 A P` — `S 68R A 68 N P` (WHO_AM_I), далі спроба 1: `S 68W A 6B A`, SCL = 0 |
| 2,533377 | SCL↑, два STOP-фронти без START (як «nack після wr2») — запис вказівника 0x6B не вийшов на шину; далі `S 68R A 40 N P`; спроба 2: `S 68W A 6B A`, SCL = 0 |
| 2,639373 | те саме: STOP-фронти без START, `S 68R A 40 N P`; спроба 3: `S 68W A 6B A`, SCL = 0 |
| 2,745368 | те саме: STOP-фронти без START, `S 68R A 40 N P`; шина вільна |
| 2,751984 | ініціалізація LCD (0x27) |

SCL у 0 між спробами: 105,2 / 105,5 / 105,5 мс. Після кожної невдалої спроби зворотне читання на шині **є** і повертає 0x40
(SLEEP = 1), а запису вказівника регістра перед ним на шині **немає**.

|---|---|---|---|---|

Обидва імпульси у вікні вже нової ширини. Перший з'являється не одразу після запису CCR, а з наступного періоду ШИМ (preload).

## ADC (D5)

2 імпульси, кожен **40,35 мкс** (`HAL_ADC_Start` → `PollForConversion` → `GetValue` для gate і для class); перший починається через 38,50 мкс після фронту D4,
другий — через 136,85 мкс; пауза між ними 58,00 мкс.

## UART (D3, 115200 8N1)

- Байти: `55 55 41 52 54 2D 54 45 53 54` = 0x55 + "UART-TEST" (10 байтів), помилок кадру немає.
- Біт (по 0x55: 9 інтервалів між фронтами від старт-біта до стоп-біта): **8,689 мкс** (інтервали 8,700 / 8,675 мкс).
  Метод найменших квадратів по всіх 72 фронтах 10 кадрів (зсув фронту від старт-біта = k · T_біт): **T_біт = 8,6875 мкс → 115 108 бод**.
  Теоретично 1/115200 = 8,6806 мкс; для BRR = 417 — 417 / 48 МГц = 8,6875 мкс.
- Кадр 10 біт = 86,9 мкс; байти йдуть з періодом 91,9 мкс, тобто між кадрами ~5,0 мкс простою.
- D4 падає через 14,3 мкс після старт-біта 10-го байта ('T'), а не після його стоп-біта (кінець — через 936,2 мкс після фронту D4).
  Тому вікно uart триває до +941 мкс, а не до спаду D4 + запас. Наступний байт ("\r" з printf) починається на 942,25 мкс.
