# План відео ЛР4 (2-3 хв)

Що має бути у відео за методичкою ЛР4 (розділ 10): обидві прошивки в сценарії S3 поруч або послідовно - видно різницю в реакції на подію під час довгої операції; вивід run-time stats і запасу стеків; фрагмент хронології задач на логічному аналізаторі. Усе - у Wokwi для VS Code, без `wokwi-cli`: S3 тут іде з моїми діями руками, як у відео ЛР3, а запис аналізатора дає сама вкладка Wokwi після Stop.

## Підготовка

1. Збірки з чистого дерева (у банері `BOOT` має бути git-хеш з `main`), обидві ELF зберегти окремо, щоб у відео перемикати прошивку копіюванням, а не збиранням (Wokwi для VS Code перезапускає симуляцію, щойно змінюється `firmware/build/firmware.elf`):
   ```
   make build ARCH=superloop LTO=1 && cp firmware/build/firmware.elf ~/lr4-superloop.elf
   make build ARCH=rtos LTO=1 && cp firmware/build/firmware.elf ~/lr4-rtos.elf
   ```
2. VS Code: зліва вкладка Wokwi (стенд), справа два термінали - для `run_scenario.py` і для команди копіювання ELF. Вкладка симулятора весь час видима, інакше Wokwi ставить симуляцію на паузу.
3. Запис аналізатора rtos для фрагмента хронології - знімаю заздалегідь, не у відео: `cp ~/lr4-rtos.elf firmware/build/firmware.elf`, ~15 с роботи, Stop у вкладці Wokwi, перейменувати `wokwi.vcd` на `docs/captures/vscode_rtos_<дата>.vcd` і попросити Claude вирізати вікно навколо перемальовки LCD (`tools/vcd_window.py`, як `docs/lab_4/captures/05-gate-superloop-s1.vcd`).
4. PulseView - дві вкладки з готовими курсорами (Import Value Change Dump, Downsampling factor 100, як у ЛР3):
   - `docs/lab_4/captures/05-gate-superloop-s1.vcd` - D6, D7, курсори на фронтах D7 (37,4 мс);
   - вікно rtos з п. 3 - D0, D1, D6, D7, курсори на двох сусідніх фронтах D0 посеред D7 (5,00 мс).
5. Запис екрана - OBS, 1920 × 1080, звук з мікрофона. Кожен S3 - 60 с часу МК (~1,5-2 хв реального), тож у монтажі потік прискорити ×2-3 і лишити моменти з кнопкою.
6. Логи, які `run_scenario.py` запише під час відео в `docs/metrics/lab4/`, у звіт не йдуть (числа звіту - з прогонів частини А і Б), їх не комічу.

## Що робити руками, покроково

1. Перед записом: п. 1-4 підготовки; переконатися, що в обох збірках `BOOT git=` однаковий.
2. Відкрити OBS, сцену з VS Code на весь екран, перевірити рівень мікрофона (піки не вище -6 дБ).
3. Почати запис, сказати вступ (0:00-0:30) на тлі `tasks.png`.
4. Super loop: команда копіювання ELF, `run_scenario.py`, Enter після підказки; поки йде потік - 3-4 коротких кліки B1, потім одне довге натискання і ще одне для повернення. Дочекатися кінця сценарію (≈ 60 с часу МК).
5. rtos: копіювання ELF, той самий сценарій; 2-3 коротких кліки B1 і одна посилка; після фіналу ввести `tasks`.
6. Перемкнутися в PulseView: спершу вкладка super loop, потім rtos, на кожній - назвати Δ між курсорами.
7. Завершити підсумком на таблиці 4.5, зупинити запис.
8. Монтаж: прискорити потоки S3 ×2-3, вирізати очікування збирання і старту; перевірити довжину (2:00-3:00) і гучність (нормалізація до ~-14 LUFS, піки не вище -1 дБ).
9. Завантажити на Google Drive з доступом за посиланням, посилання - в шапку docs/lab4-report.md (рядок «Відео»), перезібрати docx і pdf.
