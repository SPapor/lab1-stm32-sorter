# Записи логічного аналізатора ЛР3

Сюди я складаю записи `wokwi.vcd` зі сценаріїв ЛР3 (методичка, розділ 6). Канали такі, як у `diagram.json` і docs/pinout.md, розділ 1:

| Канал | Сигнал | Пін |
|---|---|---|
| D0 | I2C1_SCL | PA9 |
| D1 | I2C1_SDA | PA10 |
| D2 | ШІМ серво (TIM3_CH1) | PA6 |
| D3 | USART2_TX | PA2 |
| D4 | LD4: фронт - знайдено посилку (PARCEL_IN), спад - записано CCR серво | PA5 |
| D5 | кнопка E-STOP | PC13 |
| D6 | працює будь-яка задача | PB13 |
| D7 | працює lcd_task | PB14 |

Wokwi для VS Code завжди пише запис у `wokwi.vcd` у корені проєкту (він у `.gitignore`), тому після прогону файл треба перейменувати і перенести сюди. Короткий шматок навколо події вирізає `tools/vcd_window.py`.

Що ще треба записати в Wokwi (поки нічого не записано):

| Файл | Сценарій | Що дивлюся |
|---|---|---|
| `S1_idle.vcd` | S1, простій: ~5 с нічого не чіпати | D6 - ширина і період імпульсів gate (5 мс) та imu (10 мс); D7 - скільки триває lcd_task (за розрахунком ~31,5 мс) раз на 500 мс |
| `S2_parcel.vcd` | S2: затінити gate, потім відкрити | від фронту D4 до першого імпульсу нової ширини на D2 - повна затримка FR-03; ширина імпульсу D4 має збігтися з `parcel_latency` |
| `S3_estop_during_lcd.vcd` | 6.2.2: тиснути E-STOP, поки йде lcd_task (D7 = 1) | від спаду D5 до імпульсу estop_task на D6 (не менше 20 мс антибрязкоту плюс очікування своєї черги) |
| `S3_uart_stream.vcd` | 6.2.3: слати команди без пауз, поки йде lcd_task | відповіді на D3; чи стільки ж відповідей, скільки команд, і що каже `stats` у рядку `UART rx=… ore=…` |
