# Записи логічного аналізатора ЛР3

Сюди я складаю записи `wokwi.vcd` зі сценаріїв ЛР3 (методичка, розділ 6). Канали такі, як у `diagram.json` і docs/pinout.md, розділ 1:

| Канал | Сигнал | Пін |
|---|---|---|
| D0 | I2C1_SCL | PA9 |
| D1 | I2C1_SDA | PA10 |
| D2 | ШІМ серво (TIM3_CH1) | PA6 |
| D3 | USART2_TX | PA2 |
| D4 | LD4: фронт - знайдено посилку (PARCEL_IN), спад - записано CCR серво | PA5 |
| D5 | кнопка E-STOP | PC13 |
| D6 | працює будь-яка задача | PB13 |
| D7 | працює lcd_task | PB14 |

Wokwi для VS Code завжди пише запис у `wokwi.vcd` у корені проєкту (він у `.gitignore`), тому після прогону файл треба перейменувати і перенести сюди. Короткий шматок навколо події вирізає `tools/vcd_window.py`.

Записи кроку 4 (`<сценарій>_<дата>_<час>.vcd`) зроблені без вікна, через `tools/run_scenario.py --wokwi ... --vcd` (docs/scenarios.md). У них немає каналів D0, D1 (I²C) і D3 (UART TX): з ними буфер аналізатора Wokwi (1 млн змін) заповнюється за ~24 с. Запис покриває весь прогін, разом з setup і final, тож для порівняння з лічильниками треба брати вікно між `stats reset` і `stats`.

Що записано і де це в результатах (docs/metrics/results.md):

| Файл | Сценарій | Що дивлюся |
|---|---|---|
| `S1_2026-11-12_1306.vcd` | S1, простій | D6 - час задач і «дірки» між ними, D7 - lcd_task (38,2 мс, з NACK на LCD - 71,7 мс) |
| `S2_2026-11-12_1904.vcd` | S2, 30 посилок | від фронту D4 до нової ширини ШІМ на D2 - FR-03 від виявлення (3,3-22,6 мс, n=30), ширина D4 - PARCEL_IN -> CCR (3,1-3,2 мс); D7 до 105,4 мс - два NACK в одній перемальовці |
| `S3_2026-11-12_1908.vcd` | S3, потік `stats` + посилки + E-STOP | те саме, що в S2, під навантаженням; D5 - 30 натискань B1 (по черзі 150 і 450 мс), прошивка зарахувала 25 |
| `6.2.2_2026-11-12_1317.vcd` | 6.2.2, 40 натискань B1, LCD кожні 100 мс | від спаду D5 до старту estop_task на D6 - третій спосіб виміряти затримку E-STOP |
| `6.2.4_2026-11-12_1320.vcd` | 6.2.4, `TEST_I2C_FAULT=1` і `sda_gnd` | D6 - скільки цикл стоїть на перевірці 0x69 (37,5 мс) і на затиснутій SDA (до 94,8 мс) |
| `impact_2026-11-12_1903.vcd` | удар (FR-04, FR-05) | D4 і D2 - посилки з ударом ідуть на 180° (брак), без удару - на 0° |
| `6.2.7-fault_2026-11-12_1911.vcd`, `6.2.7-fault_2026-11-12_1911_lcd.png` | старт без MPU-6050 (FR-08) | знімок LCD на 3-й секунді: «FAULT:» / «MPU not found» |

`S2_2026-11-12_1311.vcd` і `S3_2026-11-12_1313.vcd` - записи кроку 4 (10 посилок, 8 натискань). У кроці 5 їх замінили S2 і S3 вище, а самі файли лишаються для історії.

Запису UART для 6.2.3 (D3) немає: у прогонах `wokwi-cli` цього каналу немає, а 6.2.3 я ганяв у VS Code. Втрати там видно з лічильників (`UART rx` проти надісланого).
